# Отсечка — Godot

Отдельная реализация игры на Godot 4.7.2: клиент Windows и авторитетный выделенный сервер Godot. Java для запуска не нужна. Текущий клиент — приложение, а не браузерная страница.

Исходный проект `cutoff-game-legacy` используется только для чтения. Этот проект от него при запуске не зависит.

## Быстрая локальная проверка

1. Дважды нажми **`Играть.cmd`** в этой папке. Запустятся локальный сервер в фоне и клиент, который сам подключится к `127.0.0.1:9080`.
2. Нажми **«Создать комнату»**.
3. Для проверки одному нажми **«Одиночная тренировка»**. Готовность для неё не требуется.
4. Для обычного матча открой **`Ещё игрок.cmd`**, нажми в первой комнате «Копировать код», вставь его во втором окне через Ctrl+V. Оба игрока нажимают **«Готов / не готов»**, затем создатель нажимает **«Начать матч»**.

В тренировке число участников для кооперативных шлюзов и отсечек равно одному. Это настройка симуляции: файл карты не меняется. Обычный матч сохраняет исходные требования механизмов, случайный план отсечек и приватные данные терминалов. На этой карте обычный матч требует минимум двух игроков.

`Остановить сервер.cmd` завершает только локальный сервер этого проекта, записанный запускателем. Обычно это не требуется: локальный сервер сам завершается после 60 секунд без подключённых клиентов. Закрытие первого игрового окна не отключает остальные окна.

Portable Godot уже находится в `tools/godot`. Если его удалить, запускатель скачает ту же официальную версию и проверит SHA256 архива. Не нужны установка Godot, Java, Maven или .NET. Для автоматических сетевых тестов дополнительно нужен Python 3; для самой игры он не нужен.

## Управление

| Действие | Клавиша |
| --- | --- |
| Движение | WASD или стрелки |
| Прицеливание | Мышь |
| Бег | Удерживать Shift |
| Рывок | Пробел |
| Взаимодействовать с пультом, ящиком, реле или терминалом | E |
| Нож / винтовка / автомат / гранатомёт / аптечка | 1 / 2 / 3 / 4 / 5 |
| Атака, лечение себя выбранной аптечкой | ЛКМ |
| Лечение или поднятие ближайшего союзника выбранной аптечкой | ПКМ |
| Перезарядка | R |
| Передать выбранные припасы ближайшему союзнику | G |
| Меню | Esc |

Автомат стреляет при удержании ЛКМ. Нож, винтовка и гранатомёт — по отдельным нажатиям. 200 стартовых HP; нокаут длится пять секунд. Аптечка восстанавливает 50 HP или поднимает союзника с 50 HP. Усилитель здоровья увеличивает максимум на 50 без лечения. Дружественный огонь включён. У закрытой двери или стены нельзя наносить урон сквозь неё.

## Продовая карта

Единственная исходная продовая карта — **`maps/emergency-reactor-copy.map`**, ручная готовая карта пользователя. Она скопирована из legacy побайтово:

```text
SHA256 bba06fe78c0d82944db42b4449fb4097b7f9537f8eff29869b9a4af2e0d67d8f
```

Сохранены размеры 11000 × 900, 176 препятствий, 74 противника, 50 ящиков, три отсечки, семь усилителей HP, исходные плиты, шлюзы, огненные карманы, мосты, заслон, реле, терминалы, триггеры появления и маршрутов. Другие карты из legacy не включены и продовыми не считаются.

Здесь перенесены игровые правила на другой движок, а не исходный Java-код. Точные ощущения от столкновений, поиска пути и поведения ИИ требуют игровой проверки и дальнейшей настройки. Графика остаётся минималистичной: тёмная сетка, простые формы, вид сверху и исходная палитра.

## Как устроена сеть

- Сервер выполняет симуляцию с фиксированным шагом 60 Гц и определяет урон, подбор предметов, триггеры и результаты отсечек.
- Клиент предсказывает своё движение тем же кодом, затем пересчитывает неподтверждённый ввод от полученного серверного состояния. Небольшие коррекции сглаживаются.
- Другие персонажи и снаряды рисуются с интерполяцией примерно на 100 мс позади входящего потока.
- Ввод передаётся 30 раз в секунду по ENet/UDP; пакет повторяет ограниченную историю команд. Каждый кадр ввода занимает 21 байт. Дискретные действия и управление комнатой передаются надёжно отдельно от снимков.
- Снимки динамического мира отправляются 20 раз в секунду, сжимаются Zstandard и делятся на части до 1000 байт. Неполный снимок отбрасывается, следующий не ждёт его восстановления.
- Сервер хранит каталог карт и выбирает карту отдельно для каждой комнаты. При подключении или смене карты клиент автоматически получает её по надёжному каналу и проверяет SHA256. Передавать файл друзьям не нужно. В каждом игровом кадре геометрия повторно не пересылается. Текущая версия протокола — 2; старый клиент нужно обновить.
- При кратком разрыве клиент автоматически возвращается с прежним персонажем. Сервер хранит сессию 90 секунд после обнаружения отключения и останавливает ввод отключившегося игрока.
- Содержимое неоткрытых ящиков и неизвестное число выживших не раскрываются в сетевых снимках. Подсказку терминала получает только прочитавший её игрок.
- Комнаты находятся в памяти и исчезают после перезапуска процесса. Матчи не сохраняются на диск.

## Оригинальный редактор карт

В проект перенесён браузерный редактор из legacy: **исходные `editor.js` и `styles.css` скопированы без изменений**, обе HTML-секции редактора тоже сохранены. Вместо прежнего упрощённого Godot-редактора открывается оригинальный интерфейс в браузере.

Запуск: **`Редактор карт.cmd`** или **«Редактор карт»** в меню игры. Кнопка доступна до подключения, после подключения и создателю комнаты в лобби. Оставь окно «Отсечка» открытым — оно обслуживает редактор. Java, Python и отдельный веб-сервер для работы не нужны. `Редактор Godot.cmd` открывает среду разработки кода и сцен, это другой инструмент.

Перенесены:

- список карт, открытие, копирование, создание из шаблона и пустого туннеля;
- полная палитра стен, подписей, триггеров, всех связанных механизмов, предметов и шести типов противников;
- оригинальный инспектор с полями, списками, HP, патронами, уровнями ИИ, триггерами и конечной точкой маршрута;
- перемещение мышью, белые ручки изменения размера, масштаб, прокрутка, сетка и линии связей;
- отмена действий и Ctrl+Z, Ctrl+S, скачивание `.map`, восстановление черновиков браузера;
- исходная защита от потери правок при конфликтующем сохранении из нескольких вкладок.

Принятая продовая карта защищена: **«Открыть» для неё создаёт рабочую копию**. Её также можно выбрать и нажать **«Создать копию»**. Изменяй ID новой копии и название в верхних полях. Сохранение не перезаписывает исходный файл.

### Своя карта и игра с друзьями

1. Открой `Играть.cmd`, затем **«Редактор карт»** — появится вкладка браузера.
2. Открой карту, создай копию, шаблон или пустой туннель. Для готового файла есть **«Открыть .map…»** в списке карт; импорт сохраняется отдельной рабочей копией.
3. **«Сохранить карту»** записывает локальную `.map` в папку `maps`. **«Скачать .map»** скачивает текущий черновик через браузер.
4. **«Сохранить и загрузить на игровой сервер»** сначала сохраняет карту, затем ждёт подтверждения от игрового Godot-сервера. При необходимости введи ключ загрузки в браузере.
5. Вернись в окно игры кнопкой **«Вернуться в игру»**. Загруженная карта уже выбрана. Создай комнату и начни тренировку либо обычный матч. Вкладка редактора продолжит работать, пока открыта игра.
6. Друзья подключаются к серверу и вводят код комнаты; карту они получают автоматически.

Для редактирования без сервера используй `Редактор карт.cmd`. Локальное сохранение и черновики работают без игрового подключения. Чтобы загрузить карту, вернись в окно игры, подключись, затем повтори загрузку из вкладки. Кнопка **«Загрузить .map»** в игровом меню тоже сохранена.

Сервер игры хранит загрузки отдельно в `server_maps/<SHA256>.map`; каталог восстанавливается после перезапуска. Каждая комната может иметь свою карту. Смена карты до матча сбрасывает готовность. Гость не может заменить карту комнаты. На локальном сервере загрузка включена; на VPS её включает владелец параметром `--allow-map-upload`, при желании с `--map-upload-token=...`.

Редактор обслуживается только на `127.0.0.1`, обычно на порту 9081; этот порт не нужно открывать на VPS. Он использует отдельную локальную сессию. Черновики хранятся в браузере: для восстановления пользуйся тем же браузером. Пределы карты задаёт Godot-сервер: формат 4, до 512 КБ, до 64 карт в игровом каталоге. Подробности переноса и проверки — `editor/README.md`.

## Работа с исходниками и сборка

`Редактор Godot.cmd` открывает `project.godot` в portable-редакторе. Основные файлы:

- `scripts/main.gd` — комнаты, подключения, ввод, снимки, повторное подключение;
- `scripts/world.gd` — авторитетные игровые правила, оружие, противники и механизмы;
- `scripts/motor.gd` — общее движение сервера и предсказывающего клиента;
- `scripts/map_data.gd` — загрузка карты, валидация, столкновения;
- `scripts/map_store.gd` — каталог, проверка и постоянное хранение серверных карт;
- `scripts/view.gd` — минималистичная отрисовка, интерфейс, управление, звук;
- `editor/editor.js`, `editor/styles.css` — оригинальный редактор;
- `editor/integration.js` — импорт файлов и загрузка карт в игру;
- `scripts/map_editor.gd` — открытие браузерного редактора из игры;
- `scripts/editor_http.gd`, `scripts/editor_catalog.gd` — локальный HTTP-интерфейс, сохранение и версии карт.

Пересобрать переносимые папки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Build.ps1 -WithLinuxRuntime
```

Результат:

- **`build/windows/Cutoff.exe` + `cutoff.pck`** — клиент. Оба файла должны лежать рядом; серверный адрес задаётся в меню. Для игры с локальным сервером сначала открой `Играть.cmd`.
- **`build/linux-server/`** — папка будущего сервера: Linux-бинарник `godot`, пакет `cutoff.pck`, запускатель и пример службы systemd.

Используется официальный переносимый бинарник движка с пакетом игры. Это работает без установки редактора и большого набора экспортных шаблонов. Лицензия движка включена рядом с бинарниками.

## Автоматические проверки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Test-Project.ps1
```

Дополнительный `tests/revision_test.gd` проверяет все 27 маршрутов вашей карты по отдельности и со всеми 74 противниками, обе области появления, события шлюза и моста, порядок «маршрут до появления», отсутствие повторного запуска, зигзаг ИИ, параметры оружия, приватность данных и сохранение серверных карт. Подробное сравнение с оригиналом — `COMPARISON.md`.

Редактор дополнительно проверяется командами `python tests/editor_http_test.py` и `python tests/editor_http_test.py --pack`: настоящая служба Godot, неизменённые файлы редактора, сохранение на диск, конфликты вкладок, защита продовой карты и загрузка в настоящий игровой сервер.

Тест мира проверяет исходный хеш карты, движение, столкновения, рывок, появление волн, связанные механизмы, оружие, перезарядку, аптечки, отсечки и приватность подсказок. Он также измеряет нагрузку при активации 74 противников в нескольких секторах.

Сетевой тест запускает настоящий Godot-сервер и два Godot-клиента через локальные UDP-прокси с задержкой 25–40 мс в каждую сторону и потерями 3% пакетов. Проверяет готовность, старт матча, движение, взаимодействие, принудительный разрыв, возврат того же персонажа, запрет перезапуска гостем и перезапуск создателем. Режим `--custom-map` дополнительно проверяет загрузку с ключом, отклонение неверного ключа, запрет смены карты гостем и автоматическое получение новой карты всеми клиентами. Он использует отдельные порты 19120–19122 и завершает только свои процессы.

Дополнительно проверены четыре клиента и сервер из собранного пакета:

```powershell
python tests/network_test.py --players 4 --custom-map
python tests/network_test.py --pack-server --custom-map
```

В режиме четырёх клиентов используются порты 19120–19124. Последний итоговый отчёт — `artifacts/validation.json`; отдельные сетевые отчёты — `artifacts/network-test-four-players.json` и `artifacts/network-test-packed.json`.

Отчёты и логи лежат в `artifacts`. Цифры производительности получены на локальном компьютере; они не являются оценкой вместимости VPS. Полный ручной забег командой и проверка на целевом VPS остаются необходимым игровым тестированием.
