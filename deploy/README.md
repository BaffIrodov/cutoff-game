# Godot-сервер на Linux VPS

Эта папка содержит подготовленные файлы; существующий Java-сервер не изменялся. Загрузка и установка на VPS в текущую работу не входили.

## Пробный запуск после локальной проверки

Папка `build/linux-server` содержит официальный Godot 4.7.2 для Linux x86_64, пакет игры и запускатель. Нужна современная Linux-система x86_64 с поддерживаемыми Godot системными библиотеками. GPU, графический рабочий стол, Java и .NET не требуются.

Скопируй **содержимое** этой папки в отдельный каталог VPS, например `/opt/cutoff-godot`, сохраняя старую установку отдельно. После загрузки:

```sh
cd /opt/cutoff-godot
chmod +x godot start-server.sh
./start-server.sh
```

Сервер должен напечатать:

```text
CUTOFF_SERVER_READY port=9080 map=emergency-reactor-copy protocol=2
```

Открой входящий **UDP-порт 9080** в настройках VPS и его сетевого экрана. В клиенте Windows укажи IP или DNS-имя VPS без `http://` и без номера порта. Текущий клиент использует порт 9080 по умолчанию. Это прямое соединение ENet/UDP; HTTP-прокси старой браузерной игры не используется.

После проверки можно установить пример `cutoff-godot.service`, предварительно создав или выбрав непривилегированного пользователя `cutoffgame` и проверив права на папку. Команды установки службы намеренно не запускаются автоматически. Файл использует `/opt/cutoff-godot` и не заменяет прежнюю Java-службу.

## Параметры

Параметры игры идут **после** `--`:

```sh
./godot --headless --main-pack cutoff.pck -- --server --port=9080
```

- `--map=/полный/путь/custom-reactor.map` — карта сервера по умолчанию. Сервер сам передаёт её подключающимся клиентам.
- `--map-directory=/opt/cutoff-godot/server_maps` — постоянный каталог пользовательских `.map`. По умолчанию `server_maps` рядом с бинарником. Пользователь службы должен иметь право записи в него. При обновлении игры сохраняй эту папку.
- `--allow-map-upload` — разрешить загрузку карт из игрового клиента. По умолчанию выключено.
- `--map-upload-token=твой-ключ` — необязательный ключ загрузки; владелец вводит его в клиенте. С этим параметром загрузки без правильного ключа отклоняются. Без параметра загружать карты может любой подключённый игрок вне матча, а заменять карту комнаты — только её создатель.
- `--allow-practice` — разрешить одиночную тренировку. Без флага сервер допускает обычные матчи с требованиями исходной карты.
- `--idle-exit=60` — завершаться через 60 секунд без подключённых клиентов. Для постоянной службы этот флаг не нужен.

Не добавляй `--bot`: автоматические тестовые клиенты относятся к исходному проекту и не включены в серверную сборку.

## Нагрузка и ограничения

Начни с одной комнаты на своём VPS. Следи за временем игрового шага, CPU, памятью и стабильностью сети. При 60 Гц бюджет одного шага — 16,7 мс. Текущее приложение рассчитывает комнаты последовательно в одном процессе; второе ядро не удваивает скорость одного матча автоматически.

В одном процессе предусмотрено до 16 комнат по четыре игрока, но это программный предел, а не обещанная вместимость твоего тарифа. При необходимости изоляции запускай отдельные процессы на разных портах и проверяй нагрузку.

Загруженные карты хранятся на диске и остаются после перезапуска. Карту можно загрузить через «Загрузить .map» или «Сохранить и загрузить на сервер»; гости получают её автоматически. Поддерживаются отдельные карты в разных комнатах.

Состояние матча хранится только в памяти. После перезапуска сервера игроки создают новую комнату. Механизм возврата персонажа рассчитан на обрыв связи до 90 секунд после обнаружения отключения.

Пакеты Windows и Linux нужно обновлять вместе. Полный игровой прогон на целевом Linux VPS пока не выполнен.
